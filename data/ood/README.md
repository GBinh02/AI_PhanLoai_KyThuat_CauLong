# OOD workflow

Run all commands from the repository root. Keep the four labels in order:
`clear`, `net_shot`, `short_service`, `smash`.
`net_shot` = bỏ nhỏ lưới; `short_service` = giao cầu ngắn.

## Dependencies and files

Use your existing training environment (TensorFlow/Keras, NumPy, pandas,
scikit-learn, matplotlib, MediaPipe, opencv-python), with FFmpeg and FFprobe
on PATH. `opencv-python` must include desktop GUI support for ROI selection.
Keep the original 105 clips and `models/pose_landmarker_full.task` locally.
The selected `.keras` and its JSON metadata are tracked; intermediate video,
pose features and dataset arrays remain ignored intentionally.

## Select ROI before looking at predictions

A group ROI is keyed by **video AND player_side**, not video alone.
Select a representative clip for each group. Choose a rectangle containing the
whole target body, arms and movement throughout the clip. Check ALL clips in
the group at the beginning, contact and end; use clip overrides where needed.
Do not optimize ROI based on predicted labels or accuracy.
`near/far` denotes position relative to camera, not persistent identity if sides change.

```powershell
python -m ai.pose_extraction.ood_crop select --clip data/ood/clips/net_shot/video4_t7.30.mp4
python -m ai.pose_extraction.ood_crop select --clip data/ood/clips/net_shot/video7_t9.40.mp4
```

In the second example select the FAR player. The near player is larger and may
otherwise be selected by MediaPipe. Enter saves the box; Esc cancels.
Use `--time 0.5` to select another frame and `--override` for a clip-specific box.
The default frame is 0.98 s; use `--time 0.3` for short-service clips.
Settings are saved incrementally in `data/ood/rois.json`. No sample ROI is
pre-approved: two clips cannot establish a safe ROI for all 105 samples.

```powershell
python -m ai.pose_extraction.ood_crop crop
```

Review `data/ood/cropped/manifest.csv` for missing ROIs or failed crops. Review
cropped videos and pose overlays before freezing the evaluation inputs.
The original manifest and clips are not overwritten.

```powershell
python ai/pose_extraction/extract_pose_features.py debug --clip data/ood/cropped/ood_0000.mp4 --out-video debug_pose.mp4
python -m ai.evaluation.run_ood --confirm
```

Outputs under `ai/evaluation/results/ood/`:
- `predictions.csv`: every input sample, including failures, both predictions.
- `metrics.json`: per-class metrics, confusion matrices, coverage and end-to-end accuracy.
- `comparison.csv`: metric column plus ShuttleSet test (BiLSTM), OOD BiLSTM,
  and OOD baseline. Accuracy/macro-F1 use the same pose-valid samples for both
  methods; end-to-end accuracy counts pipeline failures as incorrect.

The existing ShuttleSet baseline result stays in `ai/baseline/`.
No new test scores have been generated by adding these scripts.
Keep model, baseline thresholds, labels and preprocessing frozen during OOD testing.
The current clipping pipeline uses label-dependent durations (short_service vs
other strokes); disclose this annotation-assisted protocol in the report. It is
not a demonstration of automatic segmentation or label-free whole-match inference.
Videos with TikTok marks may be externally sourced: describe provenance accurately,
rather than calling every OOD video self-recorded. Video/side-derived person IDs
are grouping proxies, not verified unique people across videos.

## Reproducibility fixes

The model metadata specifies motion (231 features/frame), matching the saved
checkpoint, instead of silently falling back to raw (132). Its SHA-256 is checked
by the OOD evaluator. The multi-match pipeline now searches scripts/data_prep.
Split generation rejects a match assigned to multiple splits.

Inspect ignored files on your own computer with:
```powershell
git status --short --ignored
git check-ignore -v ai/models/checkpoints/bilstm_motion_seed5.json
```

Ignore rules do not remove files already tracked by Git. Missing local files
cannot be recovered by changing .gitignore alone.
